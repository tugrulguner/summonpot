---
title: Capabilities
description: Declare exact application operations and agent-owned choices.
---

Summonpot offers one declaration style for endpoints whose operations resolve deterministically and endpoints that permit bounded agent-owned decisions. The contract vocabulary includes `Operation`, `FromRequest`, `AgentChoice`, `Depends`, `Required`, and call bounds such as `Exactly(1)`.

## Current-source bounded repeated calls (unreleased)

One required typed operation may run a finite positive number of times (`1 <= minimum <= maximum`, `maximum > 1`) with a Pydantic request, at least one `FromRequest`, direct closed `Literal[str]` `AgentChoice` inputs, supported request/context bindings or immutable defaults, and exact full operation-output/endpoint-response annotation identity. Summonpot owns sequential decisions; business functions are not selector tools. It locally validates selections, shares one usage budget and deadline, resolves the model lazily, auto-finishes at maximum, and returns only the final successful canonical result; any failure aborts. Previous-result evidence is limited to 65,536 characters per decision, not an aggregate prompt budget. Explicit `tool_calls_limit` fails before provider/effects. No producer choices, `FromResult`, `after`, zero-minimum/unbounded bounds, implicit batch, or general graph. Existing Exactly(1) and producer-choice routes remain unchanged. Published v0.14.0 is untouched; milestone 3 remains partial and repeated-result addressing in chains remains next. See the [canonical contract](/reference/operations/).

## Current-source framework-owned progression (unreleased)

Current source (unreleased) supports one or more producer-backed choices with framework-owned progression. In an otherwise eligible uniquely ordered required `Exactly(1)` chain, a Pydantic request, at least one `FromRequest`, supported request/result/authenticated-context bindings or immutable defaults, and exact full terminal response annotation identity remain required. All current consumer domains are checked before selection or start. Singleton bindings resolve locally; a decision-only selector returns ambiguous tokens with no business-operation tools. The shared kernel validates and invokes the operation, then continues locally until another genuine decision is needed. The canonical terminal result returns without a final model acknowledgment. Request/principal, reservations, token domains, usage budgets and one deadline remain request-local across frontiers and corrections. Explicit `tool_calls_limit` retains the previous one-way agent suffix; `allow_direct=False` and other noneligible declarations retain their existing route. Limits remain 128 candidates and 65,536 evidence characters per binding, not an aggregate prompt/context budget. Prefix effects may precede provider-configuration failure; no rollback, effect replay or durable resume is added. Historical v0.14.0 remains exactly-one-choice. See the [operation reference](/reference/operations/) for details.

An `Operation` wraps an exact callable. Its inputs must have enforceable bindings; the supported runtime slice rejects unsupported explicit shapes during registration. `FromRequest` sources values from the validated caller model. A direct `AgentChoice` marks an argument the agent can choose; it does not grant authority beyond that registered callable.

```python
operation = Operation(
    lookup_record,
    bind={"record_id": FromRequest("record_id")},
    output=RecordResponse,
)

@summon("/records/lookup")
def lookup(request: LookupRequest, record=Required(operation, calls=Exactly(1))) -> RecordResponse:
    """Return the requested record."""
    ...
```

This fully resolved single-operation shape can bypass model setup when all supported deterministic-path requirements are met. Adding an explicit `AgentChoice` normally keeps execution in the agent runtime; the result-dependent source exception included from version 0.14.0 is documented in the [operation reference](/reference/operations/#result-dependent-source-choice-included-from-version-0140). Consult the [capability guide](https://github.com/tugrulguner/summonpot/blob/main/docs/declarative-capabilities.md) for complete contract details; fully resolved uniquely ordered chains run model-free from version 0.12.0 when every operation is required `Exactly(1)`, the endpoint has a Pydantic request with at least one `FromRequest` binding, arguments use only supported request/result bindings or immutable defaults, and the terminal output exactly matches the full endpoint response annotation. An `AgentChoice` normally keeps the chain agent-mediated; the result-dependent source exception included from version 0.14.0 is specified in the [operation reference](/reference/operations/#result-dependent-source-choice-included-from-version-0140). Broader graph execution remains planned.

Authenticated `FromContext` is included from version 0.13.0 for the supported single
required `Exactly(1)` operation and uniquely ordered required chain. The application
authenticates credentials through `Summon(context=authenticate)`; caller JSON and model
arguments cannot supply identity. Context may resolve a model-free path only when the
existing Pydantic request, at least one `FromRequest`, immutable-default, and exact full
terminal response requirements also hold. `AgentChoice` is ordinarily agent-mediated; see the [result-dependent source exception included from version 0.14.0](/reference/operations/#result-dependent-source-choice-included-from-version-0140).
See the [authenticated context contract](/reference/operations/#authenticated-application-context-included-from-version-0130).
