Summonpot modernizes APIs for the AI era. Instead of splitting application endpoints and agent workflows across separate abstractions, declare a typed endpoint whose contract states what callers may send, what the application may execute, where the agent may decide, and what the endpoint may return.

The agent's authority is bounded by the endpoint declaration. Exact application behavior stays application-owned; semantic choices are agent-owned only where the contract explicitly allows them.

## Try a complete endpoint

This endpoint takes a validated topic, lets the agent choose the operation's response
style, and requires one application-owned operation. The operation computes a candidate
summary; the model cannot supply its topic or replace its implementation. The final
model response is schema-validated, not automatically bound to that candidate.

```python
from typing import Literal

from pydantic import BaseModel, Field
from summonpot import AgentChoice, Exactly, FromRequest, Operation, Required, Summon


class SummaryRequest(BaseModel):
    topic: str = Field(min_length=1, max_length=200)


class SummaryResponse(BaseModel):
    summary: str
    style: Literal["brief", "detailed"]


def build_summary(topic: str, style: Literal["brief", "detailed"]) -> SummaryResponse:
    """Build a summary for the requested topic in the selected style."""
    length = 80 if style == "brief" else 240
    return SummaryResponse(summary=f"{topic[:length]}", style=style)


summary_operation = Operation(
    build_summary,
    bind={"topic": FromRequest("topic"), "style": AgentChoice()},
    output=SummaryResponse,
)

summon = Summon("summary-api")


@summon("/summarize")
def summarize(
    request: SummaryRequest,
    result=Required(summary_operation, calls=Exactly(1)),
) -> SummaryResponse:
    """Summarize the requested topic and choose a brief or detailed style."""
    ...
```

Save as `app.py`, install the serving extras, then start the local API:

```bash
python -m pip install 'summonpot[serve,cli]'
export SUMMONPOT_MODEL=test
summonpot serve app.py --host 127.0.0.1 --port 8000
```

The test model is keyless, **not** a side-effect-free sandbox. This example's operation is
harmless; use only harmless capabilities when wiring your own endpoint. Try it through the
same HTTP route clients use:

```bash
curl -X POST http://127.0.0.1:8000/summarize \
  -H 'Content-Type: application/json' \
  -d '{"topic":"Contract-first APIs keep application behavior explicit."}'
```

This contract requires one `Exactly(1)` operation and declares an `AgentChoice`, so the
operation's call count and the final response schema are enforced. The topic argument is
application-bound; the agent chooses the operation's style argument. The keyless test
model returns placeholder response strings, not a useful semantic summary. Response
validation does not prove that final text reproduces the operation's result.

A fully application-bound operation in the supported single-operation shape can instead
execute directly without resolving a model. Broader multi-operation deterministic
execution remains planned; see the [roadmap](https://github.com/tugrulguner/summonpot/blob/main/ROADMAP.md).

## Shipped today

- Typed contract-first endpoints and generated HTTP/OpenAPI contracts.
- Closed sets of application-owned callables; optional or required operations.
- Bounded agent runtime with locally validated response models and limits.
- A narrow, fully resolved single `Exactly(1)` operation path that executes without resolving or constructing a model.

Broader multi-operation deterministic execution is **planned**, not shipped. See the [project roadmap](https://github.com/tugrulguner/summonpot/blob/main/ROADMAP.md) and [changelog](https://github.com/tugrulguner/summonpot/blob/main/CHANGELOG.md) for current boundaries.
