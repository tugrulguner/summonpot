Summonpot modernizes APIs for the AI era. Instead of splitting application endpoints and agent workflows across separate abstractions, declare a typed endpoint whose contract states what callers may send, what the application may execute, where the agent may decide, and what the endpoint may return.

The agent's authority is bounded by the endpoint declaration. Exact application behavior stays application-owned; semantic choices are agent-owned only where the contract explicitly allows them.

## Shipped today

- Typed contract-first endpoints and generated HTTP/OpenAPI contracts.
- Closed sets of application-owned callables; optional or required operations.
- Bounded agent runtime with locally validated response models and limits.
- A narrow, fully resolved single `Exactly(1)` operation path that executes without resolving or constructing a model.

Broader multi-operation deterministic execution is **planned**, not shipped. See the [project roadmap](https://github.com/tugrulguner/summonpot/blob/main/ROADMAP.md) and [changelog](https://github.com/tugrulguner/summonpot/blob/main/CHANGELOG.md) for current boundaries.
